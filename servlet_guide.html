最初に覚えたい言葉

Tomcat（トムキャット）
サーブレットを動かすためのソフト。役割としてはアプリケーションサーバ（プログラムを実行して結果を返すサーバ）にあたる
J2EE コンテナ
Tomcat の中にある、サーブレットの実行環境。サーブレットをインスタンス化し、doGet などのメソッドを呼び出す係
サーブレット
Web サーバ上で動き、HTML を作ってブラウザに返す Java プログラム。J2EE の Web アプリケーションの最も基本的な構成要素
Request／Response
ブラウザ → サーバへの「お願い」／サーバ → ブラウザへの「返事」
パラメータ
フォームに入力され、Request に入れてサーバへ送られる値（例：名前）
ポート番号
サーバの中で動いているソフトを区別する番号。Tomcat は 8080（Web サーバの標準は 80）なので、URL に :8080 を書く
デプロイメントディスクリプタ
Web アプリの構成（どのサーブレットをどの URL で動かすか）を書く設定ファイル。実際のファイル名は web.xml

1ファイル構成：どこに何を置く？

サーブレットは「置く場所」が決まっています。テキスト p.29 と同じ構成です。

1-1. 全体の配置図

C:\tomcat10 ← Tomcat 本体（インストール済み） ├ bin │ ├ startup.bat ← Tomcat を起動する │ └ shutdown.bat ← Tomcat を停止する ├ lib │ └ servlet-api.jar ← ★ コンパイルのときに使う jar ファイル └ webapps ← Tomcat の中にある webapps フォルダ └ myapps ← URL の /myapps/ にあたる └ WEB-INF ← すべて大文字・ハイフン ├ web.xml ← サーブレットの登録ファイル └ classes ├ MyName.java ← ソース（ここでコンパイル） └ MyName.class ← コンパイルするとできる

緑の文字＝自分で作るフォルダ・ファイル

⚠️ 注意：フォルダ名は正確に

myapps は必ず C:\tomcat10\webapps の中に作ります。WEB-INF はすべて大文字で、間はハイフン（-）です。アンダーバー（_）にしないよう気をつけましょう。

1-2. 「何をどこに置くか」早見表

ファイル置き場所役割
servlet-api.jarC:\tomcat10\libサーブレット用の部品集（最初から入っている）
web.xmlC:\tomcat10\webapps\myapps\WEB-INF「この URL ならこのサーブレット」という対応表

📝 jar（ジャー）ファイルとは

たくさんの class ファイルを 1 つにまとめたファイルです（zip のようなもの）。servlet-api.jar には HttpServlet などサーブレット用のクラスが入っています。

💡 ここがポイント：フォルダと URL の対応

webapps より後ろのフォルダ名がそのまま URL になります。myapps フォルダのサーブレットは、web.xml に登録した名前で http://localhost:8080/myapps/MyName になります。

2-1. MyName.java（テキスト p.25）

C:\tomcat10\webapps\myapps\WEB-INF\classes に、VS Code で MyName.java を作ります。

import java.io.*;
import jakarta.servlet.*;
import jakarta.servlet.http.*;

public class MyName extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
        throws IOException, ServletException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<html>");
        out.println("<head>");
        out.println("<title>My Name is Fujita</title>");
        out.println("</head>");
        out.println("<body>");
        out.println("<h1>My Name is Fujita</h1>");
        out.println("</body>");
        out.println("</html>");
    }
}
部分意味
import java.io.*;出力に使う PrintWriter や IOException を使えるようにする
import jakarta.servlet.*;
import jakarta.servlet.http.*;		サーブレット用のクラスを使えるようにする。Tomcat 10 では jakarta（古い資料にある javax ではない）
extends HttpServletHttpServlet クラスを継承（機能を受け継ぐこと）して、サーブレットにする
doGet(request, response)ブラウザから GET の Request が来たときに、Tomcat が自動で呼ぶメソッド。request は届いた情報、response は返す情報
response.setContentType("text/html");「返すのは HTML です」とブラウザに伝える。text/html は HTML を表す MIME タイプ（データの種類を表す決まった書き方）。"text/html; charset=UTF-8" のように文字コードも一緒に書ける
PrintWriter out = response.getWriter();ブラウザへ文字を書き出すための「ペン」を用意する
out.println(...)HTML を 1 行ずつブラウザへ書き出す

3入力した名前を受け取る仕組み

MyName は、いつ誰が開いても同じ文字しか表示しません。入力した名前を表示するには、「入力する画面」と「受け取る処理」が必要です。

Request
ブラウザ → Tomcat

フォームの入力値が txt=山田 の形で送られる

Response
Tomcat → ブラウザ

サーブレットが名前入りの HTML を作って返す

3-1. データの流れ

文字で書くと、次のようになります。

① ブラウザ（input.html） 名前：[ 山田 ] [送信] │ │ ② 送信ボタンで Request（GET） │ http://localhost:8080/myapps/MyName?txt=山田&send=送信 ▼ ③ Tomcat（ポート 8080） web.xml を見て「/MyName → MyName クラス」と判断 │ │ ④ doGet() を呼び出す ▼ ⑤ サーブレット（MyName） n = request.getParameter("txt"); → n には "山田" が入る out.println(...) で HTML を作る │ │ ⑥ Response（できあがった HTML） ▼ ⑦ ブラウザに結果を表示 なまえは、山田です。

3-2. name 属性と getParameter の対応

HTML 側（input.html） Java 側（MyName.java） <input type="text" name="txt"> ───→ request.getParameter("txt") └──── 同じ名前にする ────┘
  • フォームの部品には name 属性で名前が付いています。送信すると「txt=山田」のように 名前=値 の組で届きます。
  • サーブレットは getParameter("txt") と同じ名前を指定して、値を取り出します。
⚠️ 注意：名前が 1 文字でも違うと受け取れない

たとえば HTML が name="txt" なのに Java で getParameter("text") と書くと、値は取れずに null（何もない）になります。画面には「なまえは、nullです。」と表示されます。

3-3. doGet と doPost の違い（GET と POST）

フォームの method 属性によって、サーブレットのどちらのメソッドが呼ばれるかが決まります（テキスト p.31）。

<form method="get" …> ───→ サーブレットの doGet が呼ばれる <form method="post" …> ───→ サーブレットの doPost が呼ばれる URL を直接入力・リンクをクリック ───→ いつも doGet が呼ばれる

いちばん大きな違いは、入力したデータを Request のどこに入れて送るかです。

GET → doGet
データを URL（リクエスト行） にくっつけて送る
GET /myapps/MyName?txt=山田&send=送信 HTTP/1.1
Host: localhost:8080
（空行）
（メッセージボディなし）
POST → doPost
データを メッセージボディ に入れて送る
POST /myapps/share HTTP/1.1
Host: localhost:8080
Content-Type: application/x-www-form-urlencoded
（空行）
txt=山田&chk=1&chk=2&send=送信

※ 実際の送信では、日本語は %E5%B1%B1… のような記号に変換されて送られます。

GET（doGet）POST（doPost）
データの入れ場所URL の後ろ（?txt=山田）メッセージボディ
アドレス欄に見えるか見える見えない
送れるデータの量少なめ（URL の長さに限りがある）多くても大丈夫
ブックマーク・URL の共有入力内容ごとできるできない
主な使いみち検索、ページの表示など「データをもらう」とき登録、ログイン、書き込みなど「データを送って処理してもらう」とき
この授業での例MyName（STEP 2）ShareServlet（課題）
⚠️ 注意：method と メソッドの組み合わせを間違えると動かない

method="post" のフォームから送信したのに、サーブレットに doGet しか書いていないと、405 エラー（その方法では受け付けていません）になります。逆も同じです。

パスワードなど人に見られたくない値は、アドレス欄に表示されない POST で送ります（ただし POST でも暗号化されるわけではありません）。

💡 課題の ShareServlet では両方を使います

フォーム（method="post"）から送ると doPost が動いて氏名を保存し、別のブラウザで URL を直接開くと doGet が動いて保存された氏名を表示します。同じサーブレットでも、どうアクセスしたかで呼ばれるメソッドが変わることを確かめましょう。

📝 setCharacterEncoding と POST

request.setCharacterEncoding("UTF-8") は、主に POST のメッセージボディの文字コードを指定するものです。課題の ShareServlet でも、doPost の最初に書かれています（テキスト p.36）。GET の URL に付いた文字は、Tomcat 10 では最初から UTF-8 として読まれます。

input.html は myapps フォルダの直下に置きます。WEB-INF の中に置くと、ブラウザから開けません（404 になります）。

📝 なぜ WEB-INF の中は開けないの？

WEB-INF は「外から見せない」ための特別なフォルダです。サーブレットの決まりで、Tomcat は WEB-INF の中のファイルをブラウザに直接渡さないようになっています。

理由は、ここに web.xml（アプリの設定） や classes（プログラム本体） が入っているからです。もし直接開けたら、http://localhost:8080/myapps/WEB-INF/web.xml のような URL で、だれでも設定やプログラムをダウンロードできてしまいます。

myapps ├ input.html ← ブラウザから直接開ける（公開する場所） └ WEB-INF ← ブラウザから直接は開けない（非公開の場所） ├ web.xml └ classes └ MyName.class

では、classes の中のサーブレットはどうやって動くのでしょうか。ブラウザはファイルを直接開くのではなく、web.xml に登録した URL（/MyName）にアクセスします。Tomcat がその URL を見て、WEB-INF の中のサーブレットを代わりに実行し、結果の HTML だけを返します。プログラムそのものは外に出ません。

つまり、ブラウザで開きたいファイル（HTML や画像）は WEB-INF の外、見せたくないファイルは WEB-INF の中に置きます。

💡 フォルダと URL の対応

C:\tomcat10\webapps\myapps\input.html は http://localhost:8080/myapps/input.html でアクセスできます。

番号書き換え意味
①request.setCharacterEncoding("UTF-8");届いたデータを UTF-8（文字コード＝文字を数値で表す決まり）として読む。日本語の文字化けを防ぐため、値を取り出す前に書く

③タイトルを「なまえ」にブラウザのタブに出る文字。好きな文字でよい
④"なまえは、" + n +"です。"固定の文字だったところに、受け取った名前 n をつなげて表示する
💡 ここがポイント：「固定表示」→「パラメータを受け取って表示」

変わったのは②と④です。②で受け取り、④で表示に使う。Request の内容に合わせて HTML を作れることが、サーブレットのいちばんの特長です。

4-3. 書き換え後の MyName.java（完成形）

import java.io.*;
import jakarta.servlet.*;
import jakarta.servlet.http.*;

public class MyName extends HttpServlet{
    public void doGet(HttpServletRequest request,HttpServletResponse response)
        throws IOException,ServletException{

            request.setCharacterEncoding("UTF-8");

            String n = request.getParameter("txt");

            response.setContentType("text/html");
            PrintWriter out = response.getWriter();

            out.println("<html>");
            out.println("<head>");
            out.println("<title>なまえ</title>");
            out.println("</head>");
            out.println("<body>");
            out.println("<h1>なまえは、" + n +"です。</h1>");
            out.println("</body>");
            out.println("</html>");
    }
}

5うまくいかないときは

困ったときは、症状に合わせて次の点を確認しましょう。

症状よくある原因確認すること
ブラウザに「このサイトにアクセスできません」と出るTomcat が起動していない／黒い画面を閉じたstartup.bat を実行し、黒い画面を閉じずにおく
404 エラーパスの間違い・置き場所が C:\tomcat10\webapps\myapps になっているか
・WEB-INF がすべて大文字・ハイフンか

7確認問題

すべて選択問題です。正しいと思うものをクリックすると、答えと解説が表示されます。

A. Tomcat とサーブレットの実行

A1. HTML ファイルを返すだけの Web サーバでは、サーブレットは動きません。サーブレットを動かしているのはどれですか。
正解は 2。サーブレットは Tomcat のようなアプリケーションサーバの中の J2EE コンテナが、インスタンスを作って doGet などを呼び出して実行しています。Web サーバは「置いてあるファイルを返す」、アプリケーションサーバは「プログラムを実行して結果を返す」と覚えましょう。
A2. 実習中に Tomcat の黒い画面を ✕ で閉じてしまいました。元に戻すにはどうしますか。
正解は 3。黒い画面を閉じると Tomcat が止まります。startup.bat で起動し直します。shutdown.bat は Tomcat を止めるときに使います。
A3. ある PC では、Tomcat が 8081 番を使う設定になっていました。この「8081」のような番号を何といいますか。また、MyName を開く正しい URL はどれですか。
正解は 2。ポート番号は、1 台のコンピュータで動く複数のサーバソフトを見分ける番号です。ホスト名のすぐ後ろに :8081 と書きます。Tomcat は通常 8080 番で、書かないと Web サーバの標準の 80 番に接続されます。
A4. web.xml（デプロイメントディスクリプタ）を置くフォルダはどれですか。
正解は 2。web.xml は WEB-INF の直下に置きます。Web アプリの構成を書いたこのファイルをデプロイメントディスクリプタといいます。
A5. コンパイルしてできた MyName.class を置くフォルダはどれですか。
正解は 3。class ファイルは WEB-INF\classes に置きます。名前のとおり「クラスを置く場所」です。置くだけでなく、web.xml への登録も必要です。
A6. 新しいサーブレットのソースを書きました。動かすまでの作業の順番として正しいものはどれですか。
正解は 2。コンパイル → 配備 → web.xml に登録 → Tomcat の再起動。web.xml の登録は再起動より前ならいつでもかまいません。この授業では classes フォルダでコンパイルするので、コンパイルした時点で配備もできています。Tomcat は一度読み込んだものを使い続けるので、最後に必ず再起動します。
A7. サーブレット名 hello を URL /greet に結びつけたい。正しい web.xml の書き方はどれですか。
正解は 1。URL との結びつけは <servlet-mapping> に、<servlet-name> と <url-pattern> で書きます。<url-pattern> は必ず / から書き始めます。

B. サーブレットのプログラム

B1. HttpServlet の完全修飾名（パッケージ名まで含めた名前）はどれですか。
正解は 3。jakarta.servlet.http.HttpServlet。Tomcat 10 では javax ではなく jakarta から始まります。MyName.java の import jakarta.servlet.http.*; を見ると分かります。
B2. パスワードを入力するフォームで、入力した値をアドレス欄に表示させたくない。<form> タグに書くものと、呼ばれるメソッドの組み合わせはどれですか。
正解は 2。method="post" で送ると doPost が呼ばれます。POST ではデータがメッセージボディに入るので、アドレス欄には表示されません（3-3）。action は送信先を書く属性です。
B3. 次の doPost の宣言の ①・② に入る組み合わせはどれですか。
public void doPost(HttpServletRequest request, ① response)
    throws IOException, ② {
正解は 2。第 2 引数は Response（返す情報）を扱う HttpServletResponse、投げる例外は IOException と ServletException（完全修飾名は jakarta.servlet.ServletException）です。doGet と同じ形です。
B4. すべて name="hobby" のチェックボックスで、選ばれた値を全部受け取りたい。正しい 1 行はどれですか。
正解は 4。値が複数あるので getParameterValues を使います。戻り値は String の配列 String[] です。getParameter の戻り値は String で、値を 1 つしか受け取れません。
B5. 「返すのは HTML で、文字コードは UTF-8」とブラウザに伝える 1 行はどれですか。
正解は 1。Response のデータ形式は setContentType で指定します。text/html は HTML を表す MIME タイプです。返す情報なので request ではなく response を使います。
B6. 課題の ShareServlet で、ブラウザ A で登録した氏名が別のブラウザ B からも見えるのはなぜですか。
正解は 3。J2EE コンテナが作るサーブレットのインスタンスは 1 つだけです。どのブラウザからのアクセスも同じインスタンスが処理するので、インスタンス変数に入れた氏名を共有することになります（テキスト p.40）。
