Request と Response を確認しよう

ブラウザとWebサーバは、裏側で何をやりとりしているのか？ ― curl で中身をのぞいてみよう

← 一覧 1. 準備 2. curl で確認 3. 中身を読もう 4. テキストと比較 5. 困ったとき 6. 確認問題 7. チェックリスト

★この実習のゴール

テキスト p.8〜9「Request と Response の確認」を、自分のパソコンで実際にやってみます。

  • 📁Tomcat に自分でフォルダと HTML ファイルを作って、ブラウザで表示できる
  • ⌨️curl（カール）コマンドで Request と Response を確認できる
  • 🔍Request と Response が「リクエスト行／ステータス行・ヘッダ・空行・メッセージボディ」でできていることを説明できる

1準備：HTMLファイルを作って配置する

まずは Tomcat に、確認用の HTML ファイルを置きます。

1-1. フォルダを作成する

最終的に、次のようなフォルダ構成を作ります。

C:\tomcat10 ├ bin │ ├ startup.bat ← Tomcat を起動する │ └ shutdown.bat ← Tomcat を停止する └ webapps └ it01 ← URL の /it01/ にあたる（これから作る） ├ WEB-INF ← 空のフォルダ（これから作る） └ time1.html ← これから作る
  1. エクスプローラーで C:\tomcat10\webapps フォルダを開きます。
  2. 何もないところで右クリックし、「新規作成」→「フォルダー」を選びます。
  3. フォルダ名を it01 にします。
  4. 作った it01 フォルダの中に入り、同じようにして WEB-INF フォルダを作ります。中身は空のままでかまいません。
⚠️ 注意：フォルダ名は正確に

it01 は「アイ・ティー・ゼロ・イチ」です（英字のオーではなく数字のゼロ）。WEB-INF はすべて大文字で、間はハイフン（-）です。アンダーバー（_）にしないよう気をつけましょう。

💡 ここがポイント：フォルダと URL の対応

C:\tomcat10\webapps\it01\time1.html に置いたファイルは、http://localhost:8080/it01/time1.html でアクセスできます。
webapps より後ろのフォルダ名・ファイル名が、そのまま URL になります。

1-2. time1.html を作成する

C:\tomcat10\webapps\it01 に、次の内容で time1.html を作成します。

<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>現在日時の表示</title>
</head>
<body>
  <h1>現在の日時</h1>
  <p>2006-09-08 6:47:10</p>
</body>
</html>
⚠️ 注意：文字化けを防ぐために

<meta charset="UTF-8"> の1行は必ず書いてください。ファイルの文字コード（UTF-8）と、HTML の中の指定をそろえることが大切です。どちらかが違うと、ブラウザで日本語が文字化けします。

VS Code は最初から UTF-8 で保存します。画面の右下に「UTF-8」と表示されていることを確認しましょう。もし「Shift JIS」などになっていたら、そこをクリック →「エンコード付きで保存」→「UTF-8」を選びます。

📝 テキストとの違い

テキストではファイル名が time1.htm ですが、この実習では time1.html で作成します。.htm は .html の古い書き方で、中身も働きも同じです（昔の Windows では拡張子を3文字までしか付けられなかったためです）。

また、テキストの例ではアクセスするたびに現在の日時が変わりますが、今回は普通の HTML ファイルなので日時は固定です。Request と Response の確認にはこれで十分です。

1-3. Tomcat を起動する

  1. C:\tomcat10\bin フォルダを開きます。
  2. startup.bat をダブルクリックします。
  3. 黒い画面（コマンドプロンプト）が開いてログが流れ、止まったら起動完了です。
⚠️ 注意

Tomcat が開いた黒い画面は、実習中は閉じないでください。閉じると Tomcat が止まります。終わったら shutdown.bat で停止します。

1-4. ブラウザで表示する

ブラウザ（Chrome または Edge）のアドレス欄に次の URL を入力します。

http://localhost:8080/it01/time1.html

「現在の日時」と日時が表示されれば成功です。

2curl（カール）コマンドで確認する

curl は、URL を指定して Web サーバとデータをやりとりするコマンドです。ブラウザの代わりに curl で Request を送り、返ってきた Response を文字で表示させます。Windows 10 以降には最初から入っています。

2-1. コマンドプロンプトを開く

  1. スタートメニューの検索欄に「cmd」と入力し、「コマンドプロンプト」を開きます。
    （Tomcat の黒い画面とは別に、新しく開きます）
  2. 日本語の文字化けを防ぐため、最初に次のコマンドを入力して Enter を押します。 
    chcp 65001
    「Active code page: 65001」と表示されれば OK です。これで画面の文字コードが UTF-8 になります。

2-2. curl を実行する

次のコマンドを入力して Enter を押します。

curl -v http://localhost:8080/it01/time1.html

-v は「詳しく表示する（verbose）」という意味のオプションです。これを付けると、Request と Response のヘッダも表示されます。

2-3. 表示結果の見方

次のような結果が表示されます（細かい値は環境によって違います）。

*   Trying [::1]:8080...
* Connected to localhost (::1) port 8080
> GET /it01/time1.html HTTP/1.1
> Host: localhost:8080
> User-Agent: curl/8.22.0
> Accept: */*
>
< HTTP/1.1 200
< Accept-Ranges: bytes
< ETag: W/"203-1763270000000"
< Last-Modified: Mon, 16 Nov 2026 04:30:00 GMT
< Content-Type: text/html
< Content-Length: 203

<html>
<head>
<meta charset="UTF-8">
<title>現在日時の表示</title>
  …（以下、time1.html の中身）
行の始まり意味
>Request（curl が Web サーバに送った内容）
<Response のヘッダ（Web サーバから返ってきた内容）
記号なしResponse のメッセージボディ（HTML の本体）
*接続の状況メモ。今回は気にしなくてよい
💡 覚え方：> は矢印が Web サーバに向かって出ていく向き、< はこちらに入ってくる向き。

3Request と Response の中身を読もう

テキスト p.5〜7 で学んだ言葉を使って、curl の結果を読んでみましょう。HTTP プロトコルでは、クライアントから Web サーバへのアクセスを Request、Web サーバからクライアントへのアクセスを Response といいます。

Request
クライアント → Web サーバ
  1. リクエスト行Request-Line
  2. ヘッダ
  3. 空行CRLF
  4. メッセージボディMessage body
Response
Web サーバ → クライアント
  1. ステータス行Status-Line
  2. ヘッダ
  3. 空行
  4. メッセージボディ

3-1. Request を読む

GET /it01/time1.html HTTP/1.1      ← リクエスト行
Host: localhost:8080               ← ヘッダ
User-Agent: curl/8.22.0            ← ヘッダ
Accept: */*                        ← ヘッダ
                                   ← 空行（CRLF）
リクエスト行
部分意味
GETデータの要求を意味します。Web サーバに保存されているファイルを要求します。
/it01/time1.htmlクライアントが要求したデータのファイル名です（URL の localhost:8080 より後ろの部分）。
HTTP/1.1HTTP プロトコルのバージョンです。
ヘッダデータを取得するために必要な情報や、補助的な情報を含みます。一つの Request に複数のヘッダを加えることができます。
ヘッダ意味
Host: localhost:8080接続先の Web サーバ名とポート番号（HTTP/1.1 では必須）
User-Agent: curl/8.22.0クライアントに関する情報（今回は curl）
Accept: */*クライアントが受け取れるデータの種類。*/* は「何でもよい」という意味
空行（CRLF）ヘッダの終わりを表します。curl の結果では > だけの行がこれにあたります。
メッセージボディクライアントから Web サーバにデータを送信するときに、そのデータを入れる部分です。今回はファイルを要求するだけなので、メッセージボディはありません。

3-2. Response を読む

HTTP/1.1 200                       ← ステータス行
Content-Type: text/html            ← ヘッダ
Content-Length: 203                ← ヘッダ
Date: Mon, 16 Nov 2026 05:00:00 GMT← ヘッダ
                                   ← 空行
<!DOCTYPE html>                    ← メッセージボディ
<html>
  …
ステータス行HTTP プロトコルのバージョン、ステータスコード（Status-Code）、テキスト（Reason-Phrase）から構成されます。
部分意味
HTTP/1.1HTTP プロトコルのバージョン
200ステータスコード。受信した Request の処理結果を 3 桁の数字で表したもの
（OK）テキスト（Reason-Phrase）。テキストの例では 200 OK となっていますが、今の Tomcat はこの部分を省略して送ります。

主なステータスコード：

ステータスコード意味よくある原因
200処理が正常に終了し、この Response にクライアントが要求したファイルが含まれている—
404Request で要求されたファイルが Web サーバに存在しなかったURL やファイル名の間違い、置き場所の間違い
500Web サーバ内部でエラーが起きたサーブレットや JSP のプログラムの誤り（後の単元で登場）
ヘッダ
ヘッダ意味
Content-Type: text/htmlメッセージボディのデータの種類（HTML であること）
Content-Length: 203メッセージボディの大きさ（バイト数）
Date: …Web サーバが Response を送った日時（世界標準時 GMT。日本時間は +9 時間）
Last-Modified: …ファイルが最後に更新された日時
空行ヘッダの終わりを表します。curl の結果では < だけの行がこれにあたります。
メッセージボディWeb サーバからクライアントに、要求されたファイル（今回は time1.html の中身）を入れて送る部分です。
💡 ここがポイント：このメッセージボディの内容がブラウザ上で表示されます。

4テキスト（p.8〜9）の例と比べてみよう

テキストの例は 2006 年ごろの Firefox と Tomcat で取ったものです。今の環境で確認すると、次のような違いがあります。

項目テキストの例今回の実習
User-AgentFirefox 1.5curl
Accept受け取りたい種類を細かく指定curl は */*（何でもよい）だけ
Accept-Language などありcurl では送られない
ステータス行200 OK200（今の Tomcat は「OK」を省略）
Content-Typetext/html;charset=Windows-31Jtext/html（文字コードの指定なし）
ServerApache-Coyote/1.1表示されないことが多い
💡 大事なこと：ヘッダの項目や値は、使うソフトや環境によって変わります。でも、「リクエスト行／ステータス行 → ヘッダ → 空行 → メッセージボディ」という形は、いつでも同じです。これが HTTP の決まりです。

curl は必要最小限のヘッダしか送りません。最低限必要なのはリクエスト行と Host ヘッダで、ブラウザはそれ以外の情報を気を利かせて付け足しています。

📝 なぜ <meta charset="UTF-8"> が必要だったのか

今回の Response の Content-Type は text/html だけで、文字コードが書かれていません。Web サーバが文字コードを教えてくれないので、ブラウザは HTML の中の <meta charset> を見て判断します。これが無いとブラウザが推測を間違え、文字化けが起きます。

5うまくいかないときは

困ったときは、症状に合わせて次の点を確認しましょう。

症状確認すること
ブラウザに「このサイトにアクセスできません」と出る
curl で「Failed to connect」と出る		 Tomcat が起動していません。C:\tomcat10\bin\startup.bat を実行し、黒い画面を閉じずにおきましょう。
404 エラーが出る ・フォルダ名が it01、WEB-INF になっているか（つづり・大文字）
・ファイルの場所が C:\tomcat10\webapps\it01 になっているか
・ファイル名が time1.html になっているか（time1.htm や Time1.html などになっていないか）
・URL のつづりがファイル名と同じか（1文字違っても 404 になります）
・それでもダメなら、Tomcat を一度停止（shutdown.bat）して再起動
ブラウザで日本語が文字化けする <meta charset="UTF-8"> が書かれているか、VS Code の右下が「UTF-8」になっているか、Ctrl + S で保存したかを確認。直したら Ctrl + F5 で再読み込み。
curl の結果で日本語が文字化けする 先に chcp 65001 を実行したか確認。ヘッダは英数字だけなので、メッセージボディが化けていても確認には困りません。

6確認問題

自分で答えを考えてから、ボタンを押して確かめましょう。

Q1. C:\tomcat10\webapps\it01\sample.html に置いたファイルにアクセスする URL を書きなさい。
答えを見る
http://localhost:8080/it01/sample.html
Q2. curl の結果で、> で始まる行と < で始まる行は、それぞれ何を表していますか。
答えを見る
> は Request（curl が Web サーバに送った内容）、< は Response のヘッダ（Web サーバから返ってきた内容）。
Q3. リクエスト行 GET /it01/time1.html HTTP/1.1 の GET は何を表していますか。
答えを見る
データの要求。Web サーバに保存されているファイルを要求することを意味する。
Q4. ステータスコード 200 と 404 の意味をそれぞれ答えなさい。
答えを見る
200 は処理が正常に終了し、要求したファイルが Response に含まれていること。404 は要求されたファイルが Web サーバに存在しなかったこと。
Q5. Request と Response に共通する「形」を、4つの部分の順番で答えなさい。
答えを見る
リクエスト行（Response ではステータス行）→ ヘッダ → 空行 → メッセージボディ
Q6. テキスト p.8 の Request（Firefox）と、curl の Request を比べて、違いを2つ書きなさい。
答えの例を見る
・User-Agent が Firefox ではなく curl になっている
・Accept が */* だけになっている
・Accept-Language や Accept-Encoding などのヘッダが送られていない　など
