隠蔽

この資料は、スーパークラス / サブクラスの関係を使って、 「なぜ隠蔽が起こるのか」「なぜ静的束縛と言えるのか」を見やすくまとめた補助資料です。

superclass subclass static binding dynamic binding hiding
まず結論

「隠蔽」の特徴は「静的束縛」にある

スーパークラス型の変数から見ると、見えるメンバは 変数の宣言型 で決まります。 つまり、実体がサブクラスでも、変数の型がスーパークラスなら、スーパークラス側の変数が見えます。

🧩
宣言型を見る
変数の型でアクセス先を決める
➡️
🖥️
コンパイル時に決定
実行前に見えるものが決まる
➡️
📌
スーパークラス側が見える
同名のサブクラス側は隠れる
覚え方： メソッドは実体を見る、 変数は宣言型を見る。 この 1 文が、オーバーライドと隠蔽の違いを見分けるコツです。
1

静的束縛と動的束縛

静的束縛（Static Binding）は、コンパイル時 に決まります。 動的束縛（Dynamic Binding）は、実行時 に実体の型で決まります。

静的束縛 / Static Binding

変数の宣言型で決まります。フィールドや static メソッドは、この見方になります。

⏱️
決まるタイミング コンパイル時
🏷️
見るもの 変数の宣言型 
A x = new B();
System.out.println(x.name);   // A の name
System.out.println(x.price);  // A の price

動的束縛 / Dynamic Binding

実体の型で決まります。インスタンスメソッドは、この見方になります。

🕒
決まるタイミング 実行時
🎯
見るもの 実際に生成された型 
A x = new B();
x.show();  // B の show()
項目 静的束縛 動的束縛
決まる時 コンパイル時 実行時
見るもの 変数の宣言型 実体の型
対象 インスタンス変数、クラス変数、クラスメソッド インスタンスメソッド
例 p.name / p.price p.show()
ポイント： オーバーライドは動的束縛、隠蔽は静的束縛です。 どちらも「同じ名前」が出てきますが、見え方のルールが違います。
2

なぜ隠蔽が必要なのか

スーパークラスとサブクラスで、同じ名前でも意味が違うことがあります。 隠蔽があると、どの型として見ているか がはっきりし、学習しやすくなります。

📦
同名でも別の値を持てる スーパークラスとサブクラスで、別々のフィールドを持てます。
🔍
読み方が明確になる 変数の宣言型を見るだけで、どこを参照するか分かります。
🎓
継承の仕組みを理解しやすい 静的束縛と動的束縛の違いを比較できます。
🧭
コードの見通しがよい 「実体」と「宣言型」を分けて考えられます。
注意： 学習では同名のメンバを使って比較しますが、実際の開発では混乱を避けるために、 同じ名前をたくさん使いすぎないほうが安全です。
3

サンプル 1：変数の宣言型が Product のとき

Product p = new Printer("Epsun-ZZZ", 45000); のように書くと、 変数 p は Product 型として扱われます。 そのため、p.name と p.price は Product 側を見ます。

コード ページ 12 の例 
class Test{
    public static void main(String args[]){
        // スーパークラスの型で変数を宣言
        Product p = new Printer("Epsun-ZZZ", 45000);

        // name と price を出力
        // この場合、静的束縛により、スーパークラスの name と price を指す
        System.out.println(p.name + "\t" + p.price);
    }
}

class Product{
    protected String name;
    protected int price;
    public Product(){
        name = "スーパークラス";
        price = 40000;
    }
}

class Printer extends Product{
    protected String name;
    protected double price;
    public Printer(String x,int y){
        // スーパークラスの引数のないコンストラクタを暗黙的に呼び出す
        name = x;
        price = y;
    }
}

見え方の図

宣言型
Product p
p は Product として見られる
➡️
実体
new Printer()
中身は Printer のオブジェクト
p.name → Product.name p.price → Product.price
実行結果
スーパークラス 40000
ここが重要： 実体は Printer でも、変数 p の型は Product です。 だから、見えるのは Product 側のメンバになります。
つまずきやすい点： new Printer() だから Printer の値が見える、とは限りません。 変数の型 が Product なら、変数から見えるのは Product 側です。
4

サンプル 2：変数の宣言型が Printer のとき

今度は Printer p = new Printer("Epsun-ZZZ", 45000); です。 この場合は変数の型も Printer なので、p.name と p.price は Printer 側を見ます。

コード ページ 13 の例 
class Test{
    public static void main(String args[]){
        // サブクラスの型で変数を宣言
        Printer p = new Printer("Epsun-ZZZ", 45000);

        // name と price を出力
        // この場合、静的束縛により、サブクラスの name と price を指す
        System.out.println(p.name + "\t" + p.price);
    }
}

class Product{
    protected String name;
    protected int price;
    public Product(){
        name = "スーパークラス";
        price = 40000;
    }
}

class Printer extends Product{
    protected String name;
    protected double price;
    public Printer(String x,int y){
        // スーパークラスの引数のないコンストラクタを暗黙的に呼び出す
        name = x;
        price = y;
    }
}

見え方の図

宣言型
Printer p
p は Printer として見られる
➡️
実体
new Printer()
参照型と実体の型が一致している
p.name → Printer.name p.price → Printer.price
実行結果
Epsun-ZZZ 45000.0
注目： 45000.0 と小数になるのは、 Printer 側の price が double だからです。
補足： コンストラクタは継承されませんが、サブクラスのコンストラクタの中で スーパークラスのコンストラクタが先に呼ばれます。ここでは super() が暗黙的に呼ばれています。
5

「隠蔽」と「データ隠蔽」は別の意味

この資料で扱う「隠蔽」は、継承の中で同じ名前のメンバが見えにくくなる という意味です。 一方、一般的なオブジェクト指向でいう「データ隠蔽」は、private で内部データを守ることです。

意味 継承の隠蔽 データ隠蔽（Information Hiding）
何を隠す？ スーパークラスの同名メンバ クラス内部のデータ
なぜ必要？ 宣言型で見えるものを分けるため 不正な変更を防ぐため
使う場所 継承 カプセル化
例 Product p = new Printer(...) private int age;
🛡️
データを守る private にして、外から勝手に書き換えられないようにする。
✅
値を確認してから入れる setAge などのメソッドで、正しい値だけ入れる。
🧱
内部実装を変えやすい 外側の使い方を変えずに、中身を変えられる。
この授業で大事なのはここ： 今回のページでは、主に 継承の隠蔽 を学びます。 データ隠蔽は別の大切な考え方ですが、今回は区別して覚えましょう。
まとめ

今日のポイント 4 つ

「どこを見ているか」を意識すると、隠蔽と静的束縛が理解しやすくなります。

1. 隠蔽は静的束縛 変数の宣言型で、見えるメンバが決まる。
2. オーバーライドは動的束縛 インスタンスメソッドは実体の型で決まる。
3. Product p と Printer p で結果が違う 同じ new Printer() でも、変数の型で見え方が変わる。
4. 別の意味の隠蔽もある private で守るデータ隠蔽は、また別の話。
最後に： メソッドは実体、 変数は宣言型。 まずはこの 1 文を覚えると、問題を読みやすくなります。
