なぜ抽象クラスが必要なのか

抽象クラスは、共通部分は親クラスにまとめたい、 でも 動きは子クラスごとに違う というときに使います。 初学者のうちは、共通の設計図 を作る仕組みだと考えると分かりやすいです。

① 共通部分をまとめる 名前や取得メソッドなど、どの子クラスにもある部分を親クラスに置けます。
② 違う部分をはっきりさせる 子クラスごとに異なる処理は抽象メソッドにして、実装を任せます。
③ 実装漏れを防ぐ 子クラスは抽象メソッドを必ずオーバーライドするので、書き忘れを防げます。
例： Human クラスでは、 name と getName() は共通です。 しかし show() は「どう表示するか」が人によって違います。 こういうときに抽象クラスが役に立ちます。
2

抽象クラスの特徴

抽象クラスは設計上、次のような特徴を持ちます。

① インスタンス化できない。 抽象クラスそのものを new することはできません。
② 抽象メソッドを持つことができる。 抽象メソッドは、内容を持たない「形式だけのメソッド」です。
③ 抽象メソッドは具象クラスで必ずオーバーライドする。 継承した側で、処理内容を実装します。
補足： 抽象メソッドは、抽象的なアルゴリズムを表現します。 ここでいう抽象的なアルゴリズムとは、内容を持たないアルゴリズム （アルゴリズムの共通形式）のことです。
3

抽象クラスの作成

抽象クラスを作成するには、クラスに abstract 修飾子を設定します。 抽象メソッドを作成するには、メソッドに abstract 修飾子を設定します。

サンプルコード abstract class Human 
abstract class Human{
    private String _name;//氏名

    public Human(String name){
        _name=name;
    }
    public String getName(){
        return _name;
    }
    public abstract void show(); //抽象メソッド
}

ポイント

  • Human は抽象クラスなので、直接インスタンス化できません。
  • show() は抽象メソッドで、内容を持ちません。
  • 抽象クラスでも、コンストラクタや通常のメソッドは作成できます。
覚え方： abstract class は「設計図」、 abstract method は「実装を後で決める約束」です。
4

抽象クラスに関する文法上の規則

抽象クラスや抽象メソッドには、次のような規則があります。

① abstract 修飾子と final 修飾子は同時に設定できない。
② 抽象クラスにはコンストラクタを作成することはできるが、そのコンストラクタからインスタンス化することはできない。
③ 抽象クラスは抽象メソッドを持つことができる（抽象メソッドを作成しなくてもよい）。
④ 抽象メソッドはブレースを含んではいけない（＝メソッドの内容を持ってはいけない）。
⑤ 抽象メソッドは private を設定できない。
⑥ 具象クラスによって抽象クラスを継承する場合、すべての抽象メソッドをオーバーライドしなければならない。
⑦ 抽象クラスに main メソッドを作成することは可能である。
⑧ 抽象クラスにクラスメソッドを作成することは可能である。
補足： 抽象クラスを抽象クラスで継承する場合は、抽象メソッドをオーバーライドしなくても良いです。

コンパイルエラーになるサンプル

抽象クラスのコンストラクタが引数付きしかない場合、サブクラスの暗黙的な super() 呼び出しでエラーになります。

コード エラーになる例 
class Test{
    public static void main(String args[]){
        Printer p=new Printer();
    }
}
abstract class Product{
    public Product(int x){
        System.out.println("Pruduct"+x);
    }
}
class Printer extends Product{
    public Printer(){
        //ここで暗黙的にスーパークラスのコンストラクタが呼ばれる
        System.out.println("Printer");
    }
}
コンパイルエラー
error: constructor Product in class Product cannot be applied to given types; required: int found: no arguments reason: actual and formal argument lists differ in length
理由： Printer のコンストラクタは、暗黙的に super() を呼びます。 しかし Product には Product(int x) しかないため、 引数なしコンストラクタが存在せず、コンパイルできません。
