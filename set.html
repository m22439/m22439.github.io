4.1

Set インタフェースの特徴

Set は「同じものを 2 回入れない」コレクションです。List と違って順序は保証されないので、 i 番目 を扱う書き方はできません。

  • 重複した要素は 1 つにまとまる
  • 順序は保証されない
  • インデックスによる操作はできない

4.2

HashSet クラス

Set の実装クラスでよく使われるのが HashSet です。 内部ではハッシュテーブルを使うので、追加・削除・検索が速いのが特徴です。

  • 順序は保証されない
  • ハッシュ値を使って要素を管理する
  • 衝突が少ないと高速に動作する

4.3

hashCode メソッド

HashSet では、要素をどこに置くかを決めるためにハッシュ値を使います。 その値を求めるのが hashCode() で、Object クラスのメソッドとして用意されています。

  • ハッシュ値は格納先を決めるために使う
  • 同じ文字列なら同じ hashCode になる
  • Set の内部動作を理解するヒントになる

4.4

Set のインスタンスを生成する方法

Set は new 演算子で実装クラスを作ります。 たとえば Set<String> set = new HashSet<String>(); のように書きます。

  • Set インタフェースそのものではなく、実装クラスを生成する
  • よく使うのは HashSet
  • 必要に応じて TreeSet や LinkedHashSet も使う

4.5

Set への要素の追加

要素を追加するときは add() を使います。 同じ値を何度追加しても、Set には 1 つ分しか残りません。

  • 追加は add()
  • 同じ要素を追加しても増えない
  • Set は重複を自動で防ぐ

4.6

Set に格納された要素の参照

Set では get() が使えません。順番が保証されないため、要素を 1 件ずつ見るときは 拡張 for 文 か Iterator を使います。

  • List のように get(i) は使えない
  • 参照するときは 1 件ずつ取り出す
  • HashSet は表示順が保証されない

4.7

Set に格納された要素の検索

ある要素が入っているか調べるときは contains() を使います。 戻り値は true / false なので、条件分岐にも使いやすいです。

  • indexOf() ではなく contains()
  • 結果は真偽値
  • HashSet でも順序に関係なく検索できる

4.8

Set に格納された要素の削除

1 つだけ削除するなら remove()、すべて削除するなら clear() を使います。 途中で要素を見ながら削除したい場合は、Iterator の remove() も使います。

  • 単一の要素は remove() で削除
  • 全部消すときは clear()
  • 繰り返し処理中の削除は Iterator の remove() が安全

4.9

TreeSet クラス

TreeSet は Set の実装クラスの 1 つで、要素を自然順序で並べます。 文字列なら文字コード順になるので、HashSet のように順番がバラバラになりません。

  • 自然順序で表示される
  • 文字列は文字コード順
  • 順番をそろえて出したいときに便利

4.10

LinkedHashSet クラス

LinkedHashSet も Set の実装クラスの 1 つです。 ハッシュテーブルと連結リストの性質を持ち、追加した順番をそのまま保てます。

  • 追加した順番が保持される
  • HashSet より表示順を見やすくしたいときに便利
  • 順番を残しつつ重複を防ぎたい場合に向く
