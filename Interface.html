深掘り

なぜJavaは「多重継承」を禁止したのか？

Javaでは class A extends B, C のような多重継承はできません。 これには明確な理由があります。下の 2 つの図を見比べてみましょう。

✕ クラスの多重継承（Javaでは禁止）

「ひし形継承」の衝突を防ぐ

もしクラスBとクラスCの両方が同じ名前のメソッド（例えば exec()）を、それぞれ違う中身で持っていたらどうなるでしょう？
クラスAで exec() を呼んだ際、「BとCのどちらの処理を実行すべきか」判断できなくなり、プログラムが混乱します。 継承関係を線で結ぶと「ひし形」になるため、ひし形継承（ダイヤモンド問題）と呼ばれます。

○ インターフェイスの複数実装（OK）

インターフェイスなら安全な理由

インターフェイスは「メソッドの名前（型）」だけを定義し、「中身の処理」を持ちません。
複数のインターフェイスを実装しても、中身を書くのは自分自身（実装クラス）なので、衝突が起こりようがないのです。

コードで確認 コンパイルエラー 
class B { void exec(){ /* 処理B */ } }
class C { void exec(){ /* 処理C */ } }

class A extends B, C { }  // ✕ extends は 1 つだけ
コードで確認 OK 
interface B { void exec(); }
interface C { void exec(); }

class A implements B, C {  // ○ 複数OK
    public void exec(){ /* Aの処理 */ }
}
結論： 多重継承は「構造を複雑にしすぎる」ため禁止されました。インターフェイスは「安全に複数の役割を持たせる」ための賢い妥協案なのです。
深掘り

なぜ変数は自動的に「定数」になるのか？

インターフェイスで double TAX = 0.5; と書くと、自動的に public static final になります。

🏛️
なぜ static なのか？ インターフェイスは new してインスタンスを作れません。だから、個別のインスタンスに属する変数を持つことは不可能で、型そのものに属する static になる必要があります。
🔒
なぜ final なのか？ インターフェイスは「設計の約束事（コントラクト）」です。実装するクラスごとに値を書き換えられてしまうと、共通の規格としての信頼性が損なわれてしまうため、定数に固定されます。
注意： メンバ変数（インスタンス変数）を持つことはできません。共通の「データ構造（状態）」を持ちたい場合は、インターフェイスではなく抽象クラスを選んでください。
1

インターフェイスの定義ルール

ルール 内容
キーワード interface で宣言し、implements で実装する。
メソッド 自動的に public abstract になる。中身 { } は書けない。
フィールド 自動的に public static final になる。必ず初期化が必要。
実装の義務 実装クラスは、定義されたすべての抽象メソッドを実装しなければならない。
同時利用 クラスの継承(extends)とインターフェイスの実装(implements)は同時に行える。
2

サンプルコード：Productインターフェイス

コード interface / implements 
interface Product {
    // 自動的に public static final になる
    double TAX = 0.5;

    // 自動的に public abstract になる
    String getSpec();
    void show();
}

class Printer implements Product {
    // 実装クラスでは必ず public をつける
    public String getSpec() {
        return "2400dpi";
    }

    public void show() {
        // 定数はそのまま利用可能
        System.out.println("税率：" + TAX);
    }
}
show() の実行結果
税率：0.5

コンパイルエラーになる理由（練習問題より）

試験や開発で間違いやすいポイントをチェック！

🚫
修飾子の間違い インターフェイスに private や protected は使えません。誰でも使えるように public である必要があります。
✏️
処理を書いた void show() { ... } のように { } を書くとエラーです。インターフェイスは「名前」だけの定義です。
📉
アクセス権の縮小 実装クラスで public を付け忘れるとエラーです（デフォルトだとアクセス権が狭くなるため）。
⚠️
static / final メソッド インターフェイスのメソッドに static や final は指定できません（※Javaの基本ルールとして）。
発展（Java 8 以降）： この資料は基本ルールで説明していますが、Java 8 以降は default メソッド と static メソッド（中身ありで書ける）、Java 9 以降は private メソッド も使えます。 なお、2 つのインターフェイスの default メソッドが同名で衝突した場合は、実装クラスでオーバーライドしないとコンパイルエラーになるため、 「最後は実装クラスが 1 つに決める」という安全設計は保たれています。
