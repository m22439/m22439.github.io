抽象クラスとインターフェイスの使い分け（テキスト72頁）

  • 抽象クラス：サプライアのデータ構造（インスタンス変数）やアルゴリズム（メソッドの中身）がある程度共通していて、さらに共通なアルゴリズムの形式（抽象メソッド）を持たせたいときに使う。
  • インターフェイス：データ構造やアルゴリズムとはあまり関係なく、共通なアルゴリズムの形式だけを持たせたいときに使う。定数リストだけを作りたいときにも向いている。
覚え方：「中身も共通にしたい → 抽象クラス」「形（メソッド名）だけ揃えたい → インターフェイス」。

下の比較表は、何も見ずに○×を書けるようにしてください（テキスト68頁）。

抽象クラスの規則（テキスト24頁）

  • abstract と final は同時に付けられない（abstractは「継承してもらう前提」、finalは「継承禁止」で矛盾する）。
  • 抽象メソッドは { } を持てない。{ } が空でもエラーになる。
  • 抽象メソッドに private は付けられない（オーバーライドできなくなるため）。
  • 抽象メソッドが1つもない抽象クラスも作れる。mainメソッドやクラスメソッドも作れる。
  • 具象クラスで継承したら、すべての抽象メソッドをオーバーライドしなければならない。抽象クラスで継承する場合は、オーバーライドしなくてもよい。

インターフェイスの規則（テキスト49頁）

  • 変数には自動的に public static final が付く。つまり定数なので、宣言と同時に必ず初期化する（int MAX; だけではエラー）。
  • { } を持たないメソッドには自動的に public abstract が付く。
  • 抽象メソッドに private、protected、static、final は付けられない。
  • 実装するクラスでは、すべての抽象メソッドを実装しなければならない。
  • 実装するメソッドには必ず public を付ける。付け忘れると「修飾子なし」になり、publicより狭くなるのでエラーになる。
interface Printable {
    int COPIES = 1;        // 自動的に public static final
    void print();          // 自動的に public abstract
}
class Report implements Printable {
    public void print() {  // public が必要
        System.out.println("レポートを" + COPIES + "部印刷");
    }
}

3. オーバーライドの規則

オーバーライドの規則は次の5つです（テキスト5頁、33〜34頁）。

  1. 戻り値の型、メソッド名、引数リストをすべて同じにする。 引数リストが違うと、オーバーライドではなく別のメソッドになる。
  2. アクセス修飾子は「同じ」か「より緩い」ものにする。 狭くするとエラー。
  3. final が付いたメソッドはオーバーライドできない。 呼び出すことはできる。なお、クラスに final を付けると継承そのものができなくなる。
  4. private のメソッドは継承されないので、オーバーライドもできない。
  5. throws の規則：例外は「減らす」のはよいが「増やす・広げる」のはダメ。
    • throws を取り除いてもよい。
    • 元と同じ例外を throws してもよい。
    • 元の例外より広い例外（そのスーパークラス、たとえば Exception）を throws するとエラー。
    • 元にないチェック例外を新しく throws するとエラー。

アクセス修飾子の広さ（左ほど緩い）

publicprotected修飾子なしprivate
どこからでも同じパッケージとサブクラス同じパッケージそのクラスの中だけ

オーバーライドする側では、元の修飾子と同じか、それより左のものを使います。元が「修飾子なし」なら、public・protected・修飾子なしの3つが使えます。元が public なら public しか使えません。

class Shop {
    public void open() throws IOException { }
}
class Cafe extends Shop {
    public void open() { }                        // OK：throws を取り除いた
    // void open() throws IOException { }         // エラー：public より狭い
    // public void open() throws Exception { }    // エラー：例外が広い
    // public int open() { return 0; }            // エラー：戻り値の型が違う
}

super でできること：サブクラスの中から、スーパークラスのメソッド（super.show()）、フィールド（super.name）、コンストラクタ（super(引数)）を使えます。

4. 隠蔽とオーバーライド、コードの読み方

スーパークラス型 変数 = new サブクラス(); のとき、どちらのクラスのものが使われるかは、メンバの種類で決まります（テキスト21頁のまとめ表）。

サブクラスで再定義したもの隠蔽かオーバーライドか使われるのは束縛
インスタンス変数隠蔽変数の型（= の左側）のクラス静的束縛
クラス変数隠蔽変数の型（= の左側）のクラス静的束縛
クラスメソッド（static）隠蔽変数の型（= の左側）のクラス静的束縛
インスタンスメソッドオーバーライドnewしたオブジェクト（= の右側）のクラス動的束縛
覚え方：「オーバーライドできるのはインスタンスメソッドだけ。それだけが右側（中身）を見る。他は全部左側（型）を見る。」

例題

class Animal {
    String type = "動物";
    String getType() { return type; }
    static String kind() { return "Animal"; }
}
class Cat extends Animal {
    String type = "猫";
    String getType() { return type; }
    static String kind() { return "Cat"; }
    void meow() { System.out.println("にゃー"); }
}
class Test {
    public static void main(String[] args) {
        Animal a = new Cat();
        System.out.println(a.type);       // 動物：変数なので左側（Animal）
        System.out.println(a.getType());  // 猫　：インスタンスメソッドなので右側（Cat）
        System.out.println(a.kind());     // Animal：クラスメソッドなので左側
        // a.meow();                      // コンパイルエラー：Animalにmeow()はない
    }
}

読み方の手順

  1. 変数の宣言を見て、「= の左側の型」と「new したクラス」をメモする（例：左 Animal、右 Cat）。
  2. 式の中のメンバが、変数・クラスメソッド・インスタンスメソッドのどれかを確かめる。
  3. 上の表で、左側と右側のどちらのクラスを見るかを決める。
  4. メソッドの中で変数を使っているときは、そのメソッドが書かれているクラスの変数を使う（上の例では、CatのgetType()が返すのはCatのtype）。

呼び出せるメソッド：変数の型（左側）のクラスにあるメソッドだけです。サブクラスにしかないメソッドは、スーパークラス型の変数からは呼べません。

5. インターフェイスとオブジェクトコンポジション

テキスト77〜79頁のHeroの例と同じ形です。題材が変わっても、書く場所と書き方は同じなので、下の「型」を覚えましょう。

interface Light {                         // ① インターフェイス：共通のメソッドの形だけ
    void turnOn();
}
class LedLight implements Light {         // ② サプライア：implements で実装
    public void turnOn() {                //    public を忘れない
        System.out.println("LEDが点きました");
    }
}
class Lamp implements Light {
    public void turnOn() {
        System.out.println("電球が点きました");
    }
}
class Room {                              // ③ クライアント
    private Light _light;                 //    インターフェイス型のインスタンス変数
    public Room(Light l) {                //    コンストラクタで格納
        _light = l;
    }
    public void setLight(Light l) {       //    setterで入れ替え
        _light = l;
    }
    public void switchOn() {
        _light.turnOn();                  //    格納したオブジェクトを通して呼ぶ
    }
}
class Test {
    public static void main(String[] args) {
        Room r = new Room(new LedLight());
        r.switchOn();                     // LEDが点きました
        r.setLight(new Lamp());
        r.switchOn();                     // 電球が点きました
    }
}

ポイント

  • Roomは、インターフェイス型（Light）の変数を持つ。LedLight型やLamp型ではないので、どちらのオブジェクトも入れられる。
  • インターフェイスは new できない。new Light() はエラー。
  • メソッドは _light.turnOn(); のように、格納した変数を通して呼ぶ。Light.turnOn(); のように型名では呼べない。
  • 実際に動くのは、そのとき格納されているオブジェクトのメソッド（動的束縛）。setterで入れ替えると、動きも変わる。
  • 関係の言い方：RoomはLedLightのクライアント、LedLightはRoomのサプライア。RoomがLightを持つのはオブジェクトコンポジション（has-a）。
  • 問題文のクラスにないメソッドを書かない。テキストのHeroの例のように transForm() を呼ぶなど、丸暗記したコードをそのまま書くと減点される。
