まず結論：変数は宣言型、メソッドは実体

a.x のような変数アクセスは、変数の宣言型 を見ます。 a.getX() のようなメソッド呼び出しは、実体の型 を見ます。

🏷️
宣言型を見る
変数の型でアクセス先が決まる

🖥️
コンパイル時に決定
これが静的束縛
➡️
🎯
実体の型を見る
メソッドは実行時に決まる
➡️
⚡

覚え方： 変数は宣言型を見る、 メソッドは実体を見る。 この 1 文が、今日のいちばん大切なルールです。

基本サンプル：MyClass と MySubClass

まずは、この 3 つのクラスをベースにします。 7つの実験は、このコードを少しずつ変えていくだけです。

ベースコード そのまま入力する 
class MyClass{
    public int x = 10;
    public int getX() {
        return x;
    }
}

class MySubClass extends MyClass{
    public int x = 20;
    public int getX() {
        return x;
    }
}

class Test{
    public static void main(String[] args){
        MyClass a = new MySubClass();
        System.out.println(a.x);
        System.out.println(a.getX());
    }
}

このコードの見方

宣言型
MyClass a
a は MyClass として見られる
➡️
実体
new MySubClass()
中身は MySubClass のオブジェクト
a.x → MyClass.x a.getX() → MySubClass.getX()
重要： x は変数なので宣言型を見る。 getX() はメソッドなので実体を見る。
3

a と b を比べると、静的束縛と動的束縛が見える

a は MyClass 型、b は MySubClass 型です。 同じオブジェクトを見ていても、変数 と メソッド で結果が変わります。

コード ページ16の考え方 
class Test{
    public static void main(String[] args){
        MySubClass b = new MySubClass();
        MyClass a = (MyClass)b; /* キャストはなくて可 */

        System.out.println(a.x + b.x);   /* 10 + 20 = 30 */
        System.out.println(a.getX() + b.getX());
        /* 両方とも MySubClass.getX() == 20 が呼び出される */
    }
}

なぜそうなる？

  1. a.x は宣言型 MyClass を見るので 10。
  2. b.x は宣言型 MySubClass を見るので 20。
  3. a.getX() は実体 MySubClass のメソッドを呼ぶので 20。
  4. b.getX() も MySubClass.getX() なので 20。
実行結果
30 40
ポイント： 変数は宣言型、 メソッドは実体。 これが、隠蔽とオーバーライドの違いです。

応用サンプル：Product と Printer

スーパークラス内で宣言されたメソッドが参照するのは、サブクラスの変数ではなく、スーパークラスの変数です。 そのあと、オーバーライドすると、サブクラスの変数を使うようになります。

サンプル1 スーパークラスの show() 
class Test{
    public static void main(String[] args){
        Product p = new Printer("Epsun-ZZZ", 45000);
        p.show();
    }
}

class Product{
    protected String name;
    protected int price;
    public Product(){
        name = "スーパークラス";
        price = 40000;
    }
    public void show(){
        System.out.println("name=" + name + "    price=" + price);
    }
}

class Printer extends Product{
    protected String name;
    protected double price;
    public Printer(String x, int y){
        name = x;
        price = y;
    }
}
サンプル2 オーバーライド後 
class Printer extends Product{
    public Printer(String x, int y){
        name = x;
        price = y;
    }

    // スーパークラスの show をオーバーライド
    public void show(){
        System.out.println("name=" + name + "    price=" + price);
    }
}
実行結果
name=スーパークラス price=40000
実行結果（オーバーライド後）
name=Epsun-ZZZ price=45000.0
ポイント： p.show() は、実体が Printer なら Printer の show() を呼びます。 これが動的束縛です。

super と this で、スーパークラスとサブクラスを同時に見る

super はスーパークラス側、 this は今いるサブクラス側を指します。 同じ名前の変数が 2 つあるときに、とても分かりやすい書き方です。

コード 見比べるための show() 
class Printer extends Product{
    protected String name;
    protected double price;

    public Printer(String x, int y){
        name = x;
        price = y;
    }

    public void show(){
        System.out.println("サブクラス");
        System.out.println("super-name=" + super.name +
                           "    sub-name=" + this.name);
        System.out.println("super-price=" + super.price +
                           "    sub-price=" + this.price);
    }
}

実行イメージ

super
Product の値
super.name / super.price
➡️
this
Printer の値
this.name / this.price
実行結果
サブクラス super-name=スーパークラス sub-name=Epsun-ZZZ super-price=40000 sub-price=45000.0
補足： this.name と name は同じ意味です。 サブクラスのインスタンス変数を指します。
7

まとめ：オーバーライドと隠蔽の違い

一番大きな違いは、オーバーライドは動的束縛、 隠蔽は静的束縛 であることです。

再定義されるメンバの種類 隠蔽かオーバーライドか 見え方のルール
クラス変数 隠蔽 宣言型で決まる
クラスメソッド 隠蔽 宣言型で決まる
インスタンス変数 隠蔽 宣言型で決まる
インスタンスメソッド オーバーライド 実体の型で決まる
隠蔽 同名のメンバが、参照する型によって見え分けられる。
オーバーライド サブクラスのインスタンスメソッドが、スーパークラスの処理を置き換える。
静的束縛 変数の宣言型を見て、コンパイル時に決まる。
動的束縛 実体の型を見て、実行時に決まる。
最後に： この単元は、どの値が入っているか ではなく、 どこを見ているか を考える単元です。 まずは 変数は宣言型、メソッドは実体 を覚えましょう。
