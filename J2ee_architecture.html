2J2EE システムのアーキテクチャ（処理の流れ）

アプリケーションサーバ上で動く Javaのプログラム が、RDBMS などの 永続化 システムにアクセスして処理を行います。

Request（行き） Response（帰り） データベースとのやりとり
💡 ここがポイント：ブラウザに表示される HTML は、あらかじめ用意されたファイルではなく、 アプリケーションサーバ上の Javaプログラムがその場で作ったものです。

📝 永続化：プログラムが終了しても消えないように、データを保存しておくこと。

3J2EE システムの層（レイヤ：Layer）構造

システムを役割ごとに「層」に分けて考えます。アプリケーションサーバ上の Javaプログラムの中は、さらに 3つの層 に分かれます。

クライアント層

ブラウザなどのクライアントで構成されます。

プレゼンテーション層 （Javaプログラム内部）

Request の受付、セッションの制御、HTML を生成して Response のメッセージボディに格納し出力します。
＝ 画面とのやりとり担当

ビジネスロジック層 （Javaプログラム内部）

業務処理を実現するための処理を行います。
＝ 判断・計算担当

インテグレーション層 （Javaプログラム内部）

RDBMS などの永続化システムとやりとりします。内部で JDBC を使ってデータベースに接続します。
＝ データベースとの窓口

リソース層

RDBMS とデータベース、XML などの永続化システムで構成されます。

💡 覚え方：上から「見せる（プレゼンテーション）→ 考える（ビジネスロジック）→ 取りに行く（インテグレーション）」。 Webサーバは層の名前には入っていませんが、クライアント層とアプリケーションサーバの間を中継しています。

4実際のシナリオ：ネットショップの注文

「注文ボタンを押してから『注文完了』が表示されるまで」に、各層で何が起きているかを順番に見てみましょう。

ブラウザ
（中継）

アプリケーションサーバ
ビジネスロジック層
アプリケーションサーバ
インテグレーション層
アプリケーションサーバ
リソース層
RDBMS ／ データベース

  • A. 注文の受付と在庫の取得 ↓

    1. 注文内容を画面で入力し送信
    2. Webサーバが受信し、アプリケーションサーバに渡す
    3. 注文内容を受け取る
    4. 在庫のチェックを行う
    5. 在庫数を取得するため SELECT 文を RDBMS に送信
    6. SELECT 文の処理を行う

  • B. 注文の記録 ↓

    1. 注文個数と在庫数を比較し、足りていれば注文処理
    2. 注文内容を UPDATE / INSERT 文として RDBMS に送信
    3. UPDATE / INSERT 文の処理を行う

  • C. 注文完了処理 ↑

    1. 書き込み完了
    2. UPDATE / INSERT 文を実行完了
    3. インテグレーション層の結果を判定
    4. 結果を確認し「注文完了」の HTML を生成
    5. HTML を Webサーバに渡す
    6. 「注文完了」の HTML をブラウザに送信
💡 流れの形に注目：A・B は上から下へ（要求が奥へ進む）、 C は下から上へ（結果が戻ってくる）。データベースに触るのは必ず インテグレーション層 を通してです。
