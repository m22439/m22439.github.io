練習問題８　Printable インターフェイス

考え方

3つのサプライア（Student・Product・Sales）はインスタンス変数の構成がばらばらです。しかし「クラス名とインスタンス変数の値を出力する」というやりたいこと（アルゴリズムの形式）は共通です。

  • 共通の形式 → インターフェイスの抽象メソッド print() として定義する
  • 具体的な中身（どの変数をどう出すか） → 各クラスがそれぞれ実装する

こうしておけば、クライアントは相手が何のクラスかを気にせず Printable 型として扱い、print() を呼ぶだけで済みます。

① インターフェイス

interface Printable {
    // クラス名とインスタンス変数の値を出力する（抽象メソッド）
    void print();
}
ポイントインターフェイスのメソッドは自動的に public abstract になるため、ここでは書かなくても構いません。

② サプライア（インターフェイスを実装するよう修正）

class Student implements Printable {
    private String _name;
    private String _address;
    public Student(String n, String a) {
        _name = n;
        _address = a;
    }
    // Printable の抽象メソッドを実装
    public void print() {
        Class c = getClass();
        String name = c.getName();
        System.out.println("クラス名：" + name);
        System.out.println("  _name    = " + _name);
        System.out.println("  _address = " + _address);
    }
}

class Product implements Printable {
    private String _name;
    private int _price;
    public Product(String n, int p) {
        _name = n;
        _price = p;
    }
    public void print() {
        Class c = getClass();
        String name = c.getName();
        System.out.println("クラス名：" + name);
        System.out.println("  _name  = " + _name);
        System.out.println("  _price = " + _price);
    }
}

class Sales implements Printable {
    private int _sale;
    private int _count;
    public void addSale(int s) {
        _sale += s;
    }
    public void addCount(int c) {
        _count += c;
    }
    public void print() {
        Class c = getClass();
        String name = c.getName();
        System.out.println("クラス名：" + name);
        System.out.println("  _sale  = " + _sale);
        System.out.println("  _count = " + _count);
    }
}
注意実装するメソッドには必ず public を付けます。付け忘れると「アクセス権を弱めようとしています」というコンパイルエラーになります（インターフェイス側のメソッドが public のため）。

③ クライアント

// クライアント：相手の具体的なクラスを知らなくてよい
class PrintClient {
    public void output(Printable p) {
        p.print();   // 動的束縛による多態性
    }
}

class Test8 {
    public static void main(String[] args) {
        Student s  = new Student("山田太郎", "東京都新宿区");
        Product p  = new Product("ノートPC", 98000);
        Sales   sa = new Sales();
        sa.addSale(5000);
        sa.addSale(3000);
        sa.addCount(1);
        sa.addCount(2);

        PrintClient client = new PrintClient();

        // 異なるクラスのオブジェクトを Printable 型の配列にまとめられる
        Printable[] list = { s, p, sa };
        for (int i = 0; i < list.length; i++) {
            client.output(list[i]);
        }
    }
}

  _address = 東京都新宿区
クラス名：Product
  _name  = ノートPC
  _price = 98000

  _sale  = 8000
  _count = 3
ポイントgetClass() は Object クラスのメソッドなので、すべてのクラスで使えます。また、実行時の実際のクラスを返すため、各クラスでクラス名を文字列で書き込む必要がありません。

練習問題９　Bank インターフェイスへの書き換え

考え方

元のプログラムは Bank クラスを親とする継承で多態性を実現していました。これをインターフェイスに置き換えます。

変更前変更後
Bank具象クラス（利息1%の処理を持つ）インターフェイス（抽象メソッド calculate のみ）
利息1%の銀行BankNihonBank（implements Bank）
MizuhoBank / RisonaBankextends Bankimplements Bank
Printer（クライアント）変更なし（引数の型 Bank がそのまま使える）

解答プログラム

class Test {
    public static void main(String[] args) {
        Bank b = new NihonBank();   // インターフェイスは new できないので実装クラスを生成
        Bank m = new MizuhoBank();
        Bank r = new RisonaBank();

        Printer p = new Printer();

        p.print(b, 10000, 5);
        p.print(m, 10000, 5);
        p.print(r, 10000, 5);
    }
}

//クライアント（変更なし）
class Printer {
    //再利用性の高いメソッド
    public void print(Bank b, int money, int months) {
        //動的束縛による多態性
        int sum = b.calculate(money, months);
        System.out.println(sum);
    }
}

//インターフェイス
interface Bank {
    int calculate(int money, int months);   // 抽象メソッド
}

//サプライア（元の Bank クラスを名称変更）
class NihonBank implements Bank {
    public int calculate(int money, int months) {
        // 利息 1%
        return (int)(money * months * 1.01);
    }
}

//サプライア
class MizuhoBank implements Bank {
    public int calculate(int money, int months) {
        // 利息 2%
        return (int)(money * months * 1.02);
    }
}

//サプライア
class RisonaBank implements Bank {
    public int calculate(int money, int months) {
        // 利息 10%
        return (int)(money * months * 1.10);
    }
}

実行結果

50500
51000
55000
よくある間違い Bank b = new Bank(); のまま残すと「Bank は abstract です。インスタンスを生成することはできません」というエラーになります。インターフェイスは型として変数宣言には使えますが、new はできません。
ポイント変数の型を Bank（インターフェイス）にしておくと、Printer クラスは一切修正せずに済みます。新しい銀行を追加するときも implements Bank したクラスを作るだけで、クライアント側は変わりません。

まとめ

項目内容
インターフェイスの役割「何ができるか」という共通の形式（抽象メソッド）だけを決める
実装クラスの役割implements して、抽象メソッドの具体的な処理を書く（public 必須）
クライアントの利点インターフェイス型で受け取れば、相手の具体的なクラスに依存しない
継承との違いクラスの継承（extends）は1つだけだが、インターフェイスは複数実装できる
